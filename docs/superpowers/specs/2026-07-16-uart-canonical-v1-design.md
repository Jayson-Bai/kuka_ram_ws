# UART 挤出边界 canonical_v1 设计

## 状态

- 日期：2026-07-16

- 用户确认：已确认执行

## 背景

上位机当前通过 RSI 心跳获得绝对挤出量，在 `uart_node` 中乘以
`extrude_scale` 后，以 ASCII 命令发送给 MCU：

```text
E <seq_used> <tool_id> <absolute_E>\n
```

当前 UART 边界使用 `double` 计算、`float` 形参和默认流格式化的组合，并在
串口写入前更新 E 去重缓存。因此，同一个逻辑 E 可能出现可变小数位或科学计数
法；文本线上值与数值去重依据也不完全一致；串口写失败后还可能错误地认为该 E
已经发送成功。

固件第一阶段继续接受现有命令语法、稀疏绝对 E、`seq_used`、初始零省略、
PAUSE 静默、旧式复位和无 ACK 闭环。本设计只收紧 UART 出口的数据规范和提交
边界，不改变上游轨迹或固件协议状态机。

## 目标

1. 保持第一阶段 ASCII 命令语法完全不变。
2. 默认将 UART E 规范化为固定 6 位小数，禁止科学计数法和负零文本。
3. 让去重依据与最终线上 E 完全一致。
4. 只有串口同步写成功后才提交 E 去重状态。
5. 保留可通过启动参数选择的旧数值格式和旧数值去重模式。
6. 把格式化、去重和提交状态从 ROS/串口 I/O 中分离，形成可独立单测的边界组件。

## 非目标

本阶段不修改：

- NPZ 的格式、`float32 e` 存储或挤出量计算公式；
- `center_node`、RSI 轨迹、4 ms 主循环和心跳字段；
- `extrude_scale` 的含义；
- PAUSE、RESUME、ABORT、事件等待或系统状态机；
- `EV 0 extrude_reset` 及其完成判据；
- `seq_used` 的语义，也不新增独立 UART 帧序号；
- ACK/EACK、E2、CRC、编码器反馈或重传协议；
- UI 的 UART 原始日志解析方式；
- MCU 的速度、加速度、保持使能和执行策略。

## 架构

### 纯 UART 边界组件

在 `uart_bridge` 包中增加不依赖 ROS 和串口的 C++ 组件，负责：

- 解析 `extrusion_wire_mode`；
- 根据模式构造待发送 E 候选项；
- 判断初始零抑制和重复 E；
- 生成完整、可直接写串口的旧协议文本；
- 在调用方明确确认写成功后提交候选项；
- 在挤出复位完成时清空已提交状态。

组件使用 `prepare -> write -> commit` 两阶段接口。`prepare` 不修改已提交
状态；`uart_node` 调用现有同步串口写函数；仅当写函数返回成功时调用
`commit`。这样既能单测失败重试，也不会把 ROS、串口对象或线程模型耦合进数值
规则。

`uart_node` 继续负责：

- PAUSE、ABORT、待处理事件等现有发送门控；
- 从心跳读取 `seq_used`、`tool_id` 和 `extrude_abs`；
- 应用 `extrude_scale`；
- 执行串口写入、原始日志发布和错误日志；
- 在复位完成后通知边界组件清空状态。

### 配置和回退

新增启动期字符串参数：

```text
extrusion_wire_mode:=canonical_v1  # 默认
extrusion_wire_mode:=legacy_v1     # 回退
```

启动文件只做参数声明和透传，不改变其他节点配置。参数不支持运行中动态切换，
避免切换时已提交去重状态含义不明确。未知值应在启动时给出明确错误并拒绝静默
降级。

## canonical_v1 规则

### 1. 输入与缩放

`uart_node` 保持现有门控顺序。允许发送时，使用 `double` 计算：

```text
scaled_e_mm = heartbeat.extrude_abs * extrude_scale
```

若输入、缩放结果不是有限数，或规范化后超出有符号 64 位整数可表达范围，则拒绝
该候选项、记录错误，并且不改变去重状态。

### 2. 规范化单位

将缩放后的 E 四舍五入为 `10^-6 mm` 整数单位：

```text
e_nm = round(scaled_e_mm * 1,000,000)
```

这里 `10^-6 mm` 等于 1 nm。`e_nm` 使用 `int64_t`，它既是固定六位文本的
唯一来源，也是 canonical 模式的去重键，避免再次经过 `float` 或依赖流的默认
有效数字精度。

### 3. 文本格式

E 文本必须由 `e_nm` 确定性生成：

- 固定保留小数点后 6 位；
- 不使用科学计数法；
- 不受系统 locale 影响；
- 量化为零的正负输入都输出 `0.000000`；
- 命令字段、空格、换行及字段顺序保持不变。

示例：

```text
1.2          -> 1.200000
0.0000004    -> 0.000000
-0.0000004   -> 0.000000
1234567.25   -> 1234567.250000
```

完整输出仍为：

```text
E <seq_used> <tool_id> <fixed6_absolute_E>\n
```

### 4. 去重

已提交键为：

```text
(tool_id, e_nm)
```

规则如下：

- 尚无已提交 E 时，`e_nm == 0` 继续省略，且不建立状态；
- 同一工具、同一 `e_nm` 不发送；
- 工具变化时，即使 `e_nm` 相同也发送；
- 已发送非零 E 后回到零必须发送 `0.000000`；
- 多个原始浮点值若最终生成相同 fixed6 文本，只发送一次；
- 挤出复位完成后清空键，重新回到初始零抑制状态。

### 5. 写入提交

候选项生成后按以下顺序处理：

```text
prepare candidate
  -> synchronous serial write
     -> success: commit candidate
     -> failure: do not commit
```

写失败后，下一个满足门控条件的 4 ms 心跳会重新计算候选项。由于协议发送绝对
E，不要求重放失败时的旧心跳；应发送下一次心跳对应的最新绝对 E，并使用该心跳
当时的 `seq_used`。

## legacy_v1 规则

`legacy_v1` 用于现场兼容回退，保留：

- 缩放结果转换为 `float` 后进入发送格式化；
- 默认流格式化产生的旧数值文本；
- 以工具号、缩放后数值和现有 epsilon 为依据的数值去重语义；
- 初始近零抑制和复位清空行为。

串口写成功后提交去重状态属于传输正确性修复，两个模式共同采用。正常成功写入
时，`legacy_v1` 的线上输出与当前实现一致；它不用于恢复写失败后错误提交这一
缺陷。

## 串口和日志兼容

现有串口写函数改为返回成功/失败，但其余命令调用方不改变控制流程。

为了不影响现有 UI 和 `/uart/raw` 消费者：

- 保持现有 `TX ` 原始日志前缀和发布时间点；
- 不新增 `TX_FAIL` 协议行或改变 RX/TX 文本结构；
- 串口写异常继续通过 ROS 错误/警告日志报告；
- 本阶段不把原始日志升级为可靠传输审计记录。

因此，去重提交以同步写函数的返回结果为准，而不是以 `/uart/raw` 日志是否发布
为准。

## 测试策略

先写失败测试，再实现。核心行为使用 C++ 单元测试验证，不依赖串口硬件：

1. 模式解析、默认模式和非法模式拒绝；
2. 普通值、负值、大值、零和负零的 fixed6 黄金文本；
3. 不产生科学计数法且不受 locale 影响；
4. fixed6 量化边界和 canonical 等价值去重；
5. 初始零抑制、非零后回零、工具切换和复位；
6. `prepare` 不提交、成功后 `commit`、失败不提交并可再次准备；
7. 非有限值和 `int64_t` 范围外输入不改变状态；
8. `legacy_v1` 的典型旧文本及 epsilon 去重行为；
9. 节点源码/集成测试确认参数接线、旧协议字段顺序和写成功后提交；
10. 运行 `uart_bridge` 相关测试及受启动参数影响的回归测试。

构建和测试必须在相关包范围内通过；若环境中存在与本改动无关的既有失败，需在
交付中明确区分并给出证据。

## 已接受的系统边界

上位机侧接受并将在固件交接文档中明确以下边界：

1. 若最后一条 E 永久丢失且之后没有任何新 E，固件无法从现有单向稀疏协议推断；
2. 在进入 UART 文本边界前已经由 NPZ `float32` 或上游处理丢失的精度无法恢复；
3. 无编码器时，上位机和 MCU 都无法确认物理失步、堵转或打滑；
4. 长时间保持 EN 的温升、电流和驱动器安全性需要由固件/硬件侧实机验证。

这些边界不是本次实现的阻塞项，但需要发给固件侧留档，并请求其确认温升与驱动
参数测试结果。

## 验收标准

- 默认模式固定输出 6 位小数，旧命令语法和换行不变；
- canonical 去重与最终文本一致；
- 串口写失败不会吞掉去重状态，后续心跳可再次发送最新绝对 E；
- `legacy_v1` 可通过启动参数回退旧数值文本和去重方式；
- PAUSE、事件、复位、RSI 和 NPZ 行为没有被改变；
- 新增测试及相关回归测试通过；
- 固件交接文档准确描述最终实现和已接受边界。
